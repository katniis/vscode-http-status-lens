# Coloring and tracking this extension’s CodeLens

Research checked against VS Code’s official API documentation and Microsoft’s VS Code source on 2026-10-19.

## Finding

There is no supported extension API to color separate words or set letter spacing on one particular CodeLens. The standard CodeLens contract carries a `Command`; its display `title` is a single string. VS Code’s renderer takes that title and renders it as a label with icon parsing, not as extension-provided rich text or styled spans. The CodeLens styling exposed by the theme is one foreground color for the CodeLens UI. See the [CodeLens and Command API](https://code.visualstudio.com/api/references/vscode-api#CodeLens), [VS Code’s CodeLens renderer](https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/codelens/browser/codelensWidget.ts), and [CodeLens theme color](https://code.visualstudio.com/api/references/theme-color#editor-colors).

## What the supported options can do

| Option | What it can style | Why it does not meet the request |
|---|---|---|
| `workbench.colorCustomizations` → `editorCodeLens.foreground` | Foreground of CodeLens UI | One color for all CodeLens, not separate method/route/status colors and not this extension’s one lens. [Theme Color docs](https://code.visualstudio.com/api/references/theme-color#editor-colors) |
| `editor.codeLensFontFamily` / `editor.codeLensFontSize` | Font family and size for CodeLens | Useful readability tweaks, but not per-provider or per-lens, and there is no CodeLens letter-spacing setting. These are editor options; VS Code’s editor configuration node is language-overridable, so a `[javascript]` or `[typescript]` override can affect those languages’ CodeLens generally—not only this extension’s. [Editor options](https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/config/editorOptions.ts), [editor configuration scope](https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/config/editorConfigurationSchema.ts), [language-specific settings](https://code.visualstudio.com/docs/configure/settings#_language-specific-editor-settings) |
| Extension color contributions / theme | Named colors used by an extension or a complete color theme | A contributed color can be consumed by APIs that accept `ThemeColor`, but CodeLens `Command.title` has no color/span field. Replacing a user’s theme would be too broad. [Contribution Points](https://code.visualstudio.com/api/references/contribution-points#contributes-colors), [Color Theme guide](https://code.visualstudio.com/api/extension-guides/color-theme) |
| `TextEditorDecorationType` | Foreground and `letterSpacing` on a range of actual document text; `before`/`after` attachments can add colored text adjacent to a decorated range | The API styles source text or its attachments, not the CodeLens widget. An attachment is anchored on the source line, so it would move the display into/alongside code rather than style the separate line above the route. Attachment options do not expose `letterSpacing`. [Decoration API](https://code.visualstudio.com/api/references/vscode-api#DecorationRenderOptions), [attachment API](https://code.visualstudio.com/api/references/vscode-api#ThemableDecorationAttachmentRenderOptions) |
| Inlay hints | Composite label parts inserted at source positions | The parts support navigation, commands, and tooltips, but have no per-part color or letter-spacing property; the inlay hint itself uses the editor’s shared hint appearance. It would also sit inline in code, not in the current CodeLens row. [InlayHint API](https://code.visualstudio.com/api/references/vscode-api#InlayHintLabelPart), [inlay-hint theme colors](https://code.visualstudio.com/api/references/theme-color#editor-colors) |
| Webview | Extension-owned HTML/CSS with precise per-span colors and letter spacing | Fully styles the summary, but it is a separate custom surface (typically a side-by-side or tabbed panel), not the native inline CodeLens row. [Webview UX guidance](https://code.visualstudio.com/api/ux-guidelines/webviews), [Webview API](https://code.visualstudio.com/api/extension-guides/webview) |

The source renderer confirms the practical boundary: it passes the title through `renderLabelWithIcons`, and the CodeLens stylesheet applies one foreground color to the containing CodeLens. The stylesheet does not expose a supported per-extension selector or CodeLens letter-spacing variable. [Renderer](https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/codelens/browser/codelensWidget.ts), [CodeLens CSS](https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/codelens/browser/codelensWidget.css).

## DevTools and CSS injection

DevTools can be used manually to inspect VS Code’s rendered DOM and temporarily try a CSS rule. That is useful as a visual experiment, but it is not a distributable extension feature: VS Code explicitly says extensions have no access to the workbench DOM and cannot apply custom CSS; it also treats the DOM structure and class names as internal and warns that custom stylesheets can break as VS Code changes. A selector targeting `.codelens-decoration` or its children could therefore break across releases and would style matching CodeLens elements generally unless it relied on unstable implementation details. [Extension restrictions](https://code.visualstudio.com/api/extension-capabilities/overview#restrictions), [CodeLens implementation CSS](https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/codelens/browser/codelensWidget.css).

## Recommendation

For the smallest stable solution, keep the current native CodeLens and retain the existing foreground colors on `res.status(...)` / `res.sendStatus(...)` source literals. If the compressed look is the immediate concern, suggest a user/workspace font-size or font-family adjustment; it can be language-overridden but will affect other CodeLens in those languages too. Do not inject CSS or alter VS Code’s installation files.

If separate colors and actual tracking in that exact above-route row are firm requirements, the extension needs either (a) a future public CodeLens rich-text/style API from VS Code, or (b) to replace that row with its own rendered surface. The supported webview route gives full styling control but changes placement/interaction; decoration attachments can preserve proximity to the route but cannot reproduce the separate CodeLens row faithfully. No currently documented API satisfies all three constraints at once: exact CodeLens placement, independently colored segments, and per-lens letter spacing.
